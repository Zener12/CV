# Тема 0.3. Лоссы и кросс-энтропия

## Что такое лосс и откуда он берётся

Лосс — это перевод «модель ошиблась» в одно число, которое можно дифференцировать.
Требований к нему два: он должен убывать, когда предсказание становится лучше,
и он должен быть гладким, чтобы у него существовал градиент.

Выбор лосса определяется не вкусом, а **тем, что выдаёт модель**. Три типовых случая:

| Задача | Выход модели | Лосс |
|---|---|---|
| Регрессия | число | MSE, MAE, Huber |
| Классификация, один класс из C | вектор из C чисел | Cross-Entropy |
| Классификация, несколько меток сразу | вектор из C чисел | BCE |

Регрессия знакома: MSE из House Prices, L1 в U-Net. Разбираем второй случай —
он главный для блока 1.

## Почему для классификации не годится MSE

Соблазн понятный: закодировать классы числами и минимизировать квадрат разницы.
Три причины, почему нет.

**Первая — числа классов не упорядочены.** Если «кошка»=0, «собака»=1, «попугай»=2,
то MSE считает, что перепутать кошку с попугаем вдвое хуже, чем с собакой.
Это выдуманная структура, её в задаче нет.

**Вторая — нет вероятностной интерпретации.** Нужно не просто «класс 3», а распределение:
насколько модель уверена. Оно нужно для порогов, для калибровки, для отбраковки
сомнительных предсказаний.

**Третья, решающая — затухание градиента.**

Пусть выход прогоняется через сигмоиду: `a = σ(z)`, где `z` — сырой выход сети.
Возьмём MSE: `L = (a − y)²`. Градиент по `z`:

```
∂L/∂z = 2(a − y) · σ'(z)
```

Множитель `σ'(z)` — производная сигмоиды. Она максимальна в нуле (0.25) и
**стремится к нулю на краях**. При `z = 6` она уже около 0.0025,
при `z = 10` — примерно 0.00005.

Худший случай: правильный ответ 1, а модель уверенно говорит 0, то есть `z = −10`.
Ошибка максимальна, а градиент почти нуль. **Чем сильнее модель ошиблась,
тем меньше сигнал на исправление.** Обучение застревает.

Кросс-энтропия эту проблему решает начисто.

## Softmax: из логитов в распределение

Сеть на выходе даёт `C` произвольных вещественных чисел — по одному на класс.
Их называют **логитами**. Они не ограничены ничем: могут быть `−7.2`, `0.3`, `15.8`.

Чтобы получить распределение, применяют softmax:

```
p_i = exp(z_i) / Σ_j exp(z_j)
```

Экспонента превращает любое число в положительное, деление на сумму нормирует так,
чтобы всё сложилось в единицу.

Три свойства:

- **Сумма ровно 1**, каждое `p_i` в `(0, 1)`. Это распределение.
- **Порядок сохраняется.** Больший логит → большая вероятность. Поэтому для предсказания
  класса softmax не нужен: `argmax` по логитам даёт тот же ответ. Softmax нужен,
  когда нужны сами вероятности.
- **Инвариантность к сдвигу.** Прибавь ко всем логитам одну константу — результат
  не изменится. На этом построен трюк численной стабильности.

Экспонента усиливает разрывы. Логиты `[1, 2, 3]` дают примерно `[0.09, 0.24, 0.67]`,
а `[1, 2, 8]` — уже `[0.001, 0.002, 0.997]`. Softmax довольно резкий; «soft» в названии —
только по сравнению с жёстким `argmax`.

## Кросс-энтропия

Формула для одного примера:

```
L = − Σ_i  y_i · log(p_i)
```

где `y` — истинное распределение. В обычной классификации оно one-hot: единица
на правильном классе, нули везде. Тогда вся сумма схлопывается в одно слагаемое:

```
L = − log(p_правильного класса)
```

**Вся кросс-энтропия — это минус логарифм вероятности, которую модель дала
правильному ответу.** Больше ничего.

| Вероятность верного класса | `−log p` |
|---|---|
| 1.0 | 0 |
| 0.9 | 0.105 |
| 0.5 | 0.693 |
| 0.1 | 2.303 |
| 0.01 | 4.605 |
| → 0 | → ∞ |

Штраф за **уверенную ошибку неограничен**. Модель, которая сказала «это точно собака»
с вероятностью 0.001, а там кошка, получает лосс 6.9. Модель, которая честно сомневалась
и дала 0.5, — 0.69, в десять раз меньше. Кросс-энтропия наказывает не столько за ошибку,
сколько за самоуверенность в ошибке.

Откуда взялась именно эта формула: минимизация кросс-энтропии эквивалентна
**максимизации правдоподобия** — поиску параметров, при которых наблюдаемые данные
наиболее вероятны. Это не эвристика, а стандартный статистический принцип, тот же,
что стоит за логистической регрессией.

## Ключевой результат: градиент

Если посчитать производную кросс-энтропии **по логитам** (то есть softmax и CE вместе,
как одну операцию), получается:

```
∂L/∂z_i = p_i − y_i
```

Разность между предсказанным распределением и истинным.

Сравни с MSE + сигмоида, где стоял убивающий множитель `σ'(z)`. Здесь его **нет**.
Градиент линеен по ошибке: ошибся сильно — сигнал сильный, ошибся слабо — слабый.
Никакого затухания при уверенной ошибке.

Это и есть причина, по которой в классификации всегда softmax + кросс-энтропия.
Они математически подогнаны друг под друга: неприятный множитель из производной softmax
сокращается с логарифмом из кросс-энтропии.

Это же выражение объясняет, почему случайно инициализированная голова портит
предобученные веса (теория блока 1): градиент `softmax(z) − y` при случайной голове —
шум, и он течёт в бэкбон.

## Численная стабильность и почему на вход идут логиты

Наивная реализация «сначала softmax, потом логарифм» ломается на реальных числах.

`exp(z)` в `float32` переполняется примерно при `z > 88` — получается `inf`.
А если какая-то вероятность численно обнулилась, `log(0)` даёт `−inf`, и дальше
по сети идёт `NaN`.

Спасает инвариантность к сдвигу: если вычесть из всех логитов их максимум, результат
softmax не изменится, но экспонента больше не переполнится. Плюс `log(exp(...))`
частично сокращается аналитически. Приём называется **log-sum-exp**.

Главное практическое следствие:

> **`nn.CrossEntropyLoss` принимает ЛОГИТЫ. Softmax она делает внутри себя,
> в устойчивом виде.**

**Что будет, если поставить softmax самому.** Ошибки не будет. Лосс посчитается.
Просто softmax применится дважды: сначала твой, потом внутренний. Двойной softmax
сглаживает распределение — логиты `[1, 2, 8]` после первого прохода становятся
`[0.001, 0.002, 0.997]`, а это уже почти равномерные числа для второго softmax.
Градиенты падают, обучение идёт медленно и до худшего результата.

Ошибки нет, `NaN` нет, метрики просто хуже. **Тихий баг.**

## Семейство лоссов в PyTorch

| Класс | Что принимает | Когда |
|---|---|---|
| `nn.CrossEntropyLoss` | **логиты** `(N, C)` | один класс из C |
| `nn.NLLLoss` | **лог-вероятности** | если `log_softmax` уже сделан вручную |
| `nn.BCEWithLogitsLoss` | **логиты** | бинарная или multi-label |
| `nn.BCELoss` | **вероятности** после sigmoid | почти никогда — численно хуже |

Правило запоминания: **всё, что с `WithLogits` в названии, — предпочтительный вариант**,
потому что объединяет активацию и лосс в устойчивую операцию.

`CrossEntropyLoss` = `LogSoftmax` + `NLLLoss`. Увидев в чужом коде `log_softmax`
в конце модели, ищи `NLLLoss`, а не `CrossEntropyLoss`.

## Softmax или sigmoid — это разные задачи

**Softmax** — классы **конкурируют**. Сумма равна единице, увеличение одной вероятности
автоматически уменьшает остальные. Подходит, когда правильный ответ ровно один:
порода собаки на фото.

**Sigmoid** — каждый выход **независим**. Никакой суммы, каждый класс отвечает
на свой вопрос «да/нет». Подходит, когда меток может быть несколько сразу:
на снимке одновременно и пневмония, и кардиомегалия.

U-Net с sigmoid на масках — правильный выбор: каждый пиксель решал свой независимый
вопрос, а не выбирал один вариант из списка.

## Формы тензоров — где ломаются чаще всего

Для `nn.CrossEntropyLoss`:

- **предсказание**: `(N, C)` — float, сырые логиты;
- **цель**: `(N,)` — **целые числа `int64` с индексами классов**, от 0 до C−1.

Цель — **не one-hot**. Самая частая ошибка новичка: передают one-hot вектор `(N, C)`
и получают либо исключение, либо молча другое поведение.

Второй по частоте промах — метки не с нуля. В Oxford-IIIT Pet классы пронумерованы
**от 1 до 37**. Передашь как есть — при `C = 37` метка `37` окажется вне диапазона
и получишь ошибку про индекс.

Для сегментации формы другие: логиты `(N, C, H, W)`, цель `(N, H, W)`. Это блок 4.

Для `nn.BCEWithLogitsLoss` всё иначе — и это главное отличие, которое путают:

- **предсказание**: `(N, C)` — логиты;
- **цель**: `(N, C)` — **`float32`**, значения `0.0` и `1.0`.

То есть здесь цель **той же формы, что и предсказание**, и **вещественная**, а не целая.
Логика простая: C независимых бинарных вопросов, на каждый свой ответ да/нет.
Индекса одного правильного класса тут не существует, поэтому и индексной метки нет.

Сводка, которую стоит помнить целиком:

| | `CrossEntropyLoss` | `BCEWithLogitsLoss` |
|---|---|---|
| задача | один класс из C | C независимых меток |
| активация внутри | softmax | sigmoid |
| форма цели | `(N,)` | `(N, C)` |
| тип цели | `int64`, индексы `0..C−1` | `float32`, значения `0.0/1.0` |

## Reduction

У всех лоссов есть параметр `reduction`:

- `'mean'` — среднее по батчу, **по умолчанию**;
- `'sum'` — сумма;
- `'none'` — вектор потерь по каждому примеру.

`'mean'` стоит по умолчанию не случайно: он делает величину градиента **не зависящей
от размера батча**. Поставишь `'sum'` — градиент вырастет пропорционально batch size,
и подобранный learning rate перестанет работать. Это ровно тот механизм, из-за которого
при gradient accumulation лосс делят на число шагов.

`'none'` нужен, когда хочешь взвесить примеры вручную или посмотреть, на каких именно
модель ошибается сильнее всего — пригодится в блоке 3.

## Дисбаланс классов — коротко

Если один класс встречается в 100 раз чаще, кросс-энтропия по умолчанию будет тянуть
модель к предсказанию мажоритарного класса: так средний лосс меньше.

Два встроенных инструмента: `weight` у `CrossEntropyLoss` (вектор весов по классам)
и `pos_weight` у `BCEWithLogitsLoss`. Подробно — блок 3.

## Диагностика: стартовый лосс

**Лосс необученной модели на C классах должен быть примерно `ln(C)`.**

Почему: при случайной инициализации все классы примерно равновероятны, `p ≈ 1/C`,
значит `−log p ≈ log C`.

| C | `ln(C)` |
|---|---|
| 2 | 0.693 |
| 10 | 2.303 |
| 37 | 3.611 |
| 1000 | 6.908 |

Если на первой итерации лосс сильно больше — почти наверняка сломаны метки,
инициализация или нормализация входа. Проверять это стоит первым делом.
